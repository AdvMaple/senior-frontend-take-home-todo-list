## 2. How I directed the AI

- **Requirements-first gate:** Wrote requirements (plan/08-requirements.md) and test plan (plan/09-test-plan.md) in advance; all agent work happens against these, not from design-by-iteration.
- **Test plan review before code:** Marked gaps and conflicts for owner review; agent does not implement until requirements are approved and test plan is signed off.
- **One-writer per directory:** Subagent tasks are scoped to a single package or narrow module (e.g., "add Button to shared/ui"); human diffs after each step and integrates.
- **Lint, typecheck, test, build are human gates:** Agent does not declare "done" until `pnpm lint && pnpm typecheck && pnpm test && pnpm build` pass; human re-runs all three after each step to catch drifts and lint escapes.
- **Skill loading before substantial work:** AGENTS.md instructs agents to run `pnpm exec intent list` and load the matched skill (e.g., `intent load @app/shared#frontend-design`) before editing UI or queries. Skills are not optional; they are the contract.

## 3. What I would do differently

- Narrow subagent delegation earlier: Do not hand a subagent a whole scaffold job (D6 haiku). Instead, start with a main agent, and use subagents only for filling in one feature or one package once the structure is locked down.
- Write the HTML mockup (D9) before assigning any UI work, not after discovering design gaps. A mockup is cheaper than code iteration; it aligns on UX upfront.
- Lock down performance budgets (D12, Q5) before writing a line of code, not after. Measure baseline and set targets early so agents optimize from the start, not retrofit.

## 5. Final judgment

AI accelerated scaffolding, test drafting, and systematic diagnosis, but it did not replace review. The most valuable corrections came from using the running application: generated Tailwind output, sequence of router navigations, and labels outside the loaded combobox page were all problems that static source review alone did not reveal. The final submission therefore treats linting, type checks, tests, and browser checks as complementary evidence rather than interchangeable signals.
