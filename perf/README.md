# Performance Budgets

## Overview

This directory contains bundle-size performance reports generated by the `pnpm perf` script.

## Deterministic Static Bundle-Budget Check

The `pnpm perf` command runs a local, deterministic verification of JavaScript bundle sizes against documented budget constraints:

- **Application entry and shared dependency chunks**: < 150 KiB each (gzipped)
- **Route/feature chunks**: < 30 KiB each (gzipped)

## Running Locally

```bash
pnpm perf
```

This command:

1. Rebuilds the application (`pnpm build`)
2. Measures gzip sizes of all JavaScript assets in `apps/web/dist/assets/`
3. Validates against budget constraints
4. Writes a report to `perf/report.json`
5. Exits with status 0 (pass) or 1 (fail)

### Report Format

`perf/report.json` contains:

- `timestamp`: ISO 8601 timestamp of the check
- `nodeVersion`: Node.js version used
- `buildSuccess`: Whether `pnpm build` completed successfully
- `budgetPass`: Whether all artifacts passed their size budgets
- `pass`: Combined pass/fail (both build and budget must pass)
- `artifacts`: Array of measured bundles with gzip sizes and budget status

## Scope & Limitations

**What this checks:**

- Static bundle size budgets (gzipped)
- Deterministic, reproducible locally
- No external dependencies or CI runners required

**What this does NOT measure:**

- Runtime performance (CPU, memory, GC)
- Lighthouse scores (interactive/perceptual metrics)
- Network latency or user experience timings
- Runtime bundle behavior or code splitting effectiveness

For interactive performance and Lighthouse measurements, use dedicated CI/production tooling (e.g., `lighthouse-ci`, WebPageTest, or production RUM). Those are documented in separate follow-up workflows, not falsely claimed as part of this static check.
